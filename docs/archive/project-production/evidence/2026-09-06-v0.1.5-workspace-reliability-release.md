Codex CLI 0.150.1 was rejected by the model service before any Project work because the configured model requires a newer
CLI. The official npm latest Codex 0.153.4 was then installed in an isolated acceptance directory, preserving global settings
and the old launch receipt. The new CLI reached doctor but stopped on `kill EPERM` during browser subprocess cleanup,
before Project creation, provider calls or an ExecutionAttempt. This is not Codex video acceptance success.

A separate engineering reproduction on fixed Node.js 22.22.3 captured SIGKILL of the owned browser process group returning
EPERM, immediately followed by an empty group process listing and ESRCH at process exit. The bounded-process close handler
threw outside its Promise error path, hiding captured child output and crashing doctor. The same issue reproduced outside
Codex; it is an intermittent shared cleanup defect. A new source release and fresh two-Agent acceptance are required.

An additional `project:check --level final` invocation reported stale narrative evidence because this public route still
expected the old narrative-baseline media/receipts, which current production does not generate. Current delivery-specific
inspection passed. The public route must align with current production authority rather than require synthetic old evidence.
