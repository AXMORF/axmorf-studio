## Verification

Before publishing, the exact local tarballs passed:

- 669/669 repository tests, package typecheck, lint, documentation checks, Catalog/Registry checks, Remotion bundle/compositions,
  both package checks, and `npm audit` with zero vulnerabilities;
- a fresh creator Workspace install from the local tarballs;
- H.264/AAC renders of both System previews with non-silent measured audio;
- real Remotion Studio playback with both audio elements fully buffered before playback.

After publishing, a second empty-cache Workspace was created exclusively from `registry.npmjs.org` using
`create-axmorf-studio@0.1.3`. Its lockfile resolved `@axmorf/studio` from the public `studio-0.1.3.tgz`; install, bootstrap, doctor,
compositions, and audit all passed. Workspace audio checksums matched the table above.
`npm audit signatures` verified registry signatures for all 250 installed packages and attestations for 49 packages.

The public-package renders measured:

| Composition           | Encoded audio      | Mean volume | Peak volume |
| --------------------- | ------------------ | ----------: | ----------: |
| `DefaultIntroPreview` | AAC, 48 kHz stereo |    -16.1 dB |     -2.4 dB |
| `DefaultOutroPreview` | AAC, 48 kHz stereo |    -18.6 dB |     -0.2 dB |

In a real browser against the public-package Studio, both audio elements used prefetched blob URLs, had `readyState=4`, and were fully
buffered at frame zero. The measured delay from clicking Play to the media `playing` event was 41.5 ms for the intro and 36 ms for the
outro. The browser console contained no warnings or errors.

The first Remotion compositions command in the empty-cache Workspace downloaded its matching Chrome Headless Shell once; subsequent
renders reused that renderer dependency. This download was unrelated to the bundled audio.
