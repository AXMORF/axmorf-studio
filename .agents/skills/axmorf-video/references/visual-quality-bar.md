# 画面质量底线

适用：Root 写 `story.filmPlan`、artDirection 与 Scene brief 之前；Scene executor 绑定后编码前，以及 commit 前自审。
本文是创作底线与自审清单，不增加 JSON 字段、文件权限、validator 或审批门槛；数值是起点估算，按内容与实测时序调整。

## 已反复出现的失败模式：一 Beat 一页幻灯片

以下信号同时出现时，成片读起来像逐页 PPT，而不是影片：

- 每个 Beat 都是同一堆叠：顶部小标签与大标题、中部带边框的插图卡片、底部说明行、常驻仓库名/日期/“示意”页脚。
- 主体画在固定正方形 viewBox 里再居中放进竖屏或横屏，只占画面四分之一左右，四周是无设计的底色。
- 主体由文档图标、方框、圆点、问号和几条线组成，没有体积、光影或细节层级。
- 相隔数秒的帧几乎相同；动作只是在卡片内逐个淡入元素，镜头与主体尺度不变。
- 同一意思同时写在标题、副标题、图内标签、说明行和字幕里。
- 覆盖数十秒、多个 Beat 的连续 Scene 只有几十行代码。

只在 brief 里写“不用卡片模板”不能避免它；必须写出替代的具体画面。

## Root：写 brief 时

- **构图语法按 Beat 变化**：compositionGrammar 不写成固定的上标题/中插图/下说明。每个 Beat 用一句话写关键画面：
  取景（特写、全景、俯视、剖面、跟随）、主体位置与大致占比、哪些层出血铺满、前景遮挡、文字所在的安静区。
  相邻 Beat 的取景应可辨地不同；连续世界可以通过推拉、换位或主体变形完成变化。
- **文字预算**：除 Composition 字幕外，同一时刻画面上最多一个短标题和一个短标签。字幕已说的意思不在画面上重复。
  来源、日期与“示意”声明放在片尾或发布说明中一次，不做每帧常驻页脚。
- **主视觉路线**：宿主有实际可调用的生图工具时，为每个连续世界生成全幅环境板和透明主体，按
  [generated artwork](generated-artwork.md) 在首次 inspect 前导入，并在 brief 中写明使用 `artwork-depth` recipe。
  没有生图工具时，在 artDirection 中写出下面的 SVG 精作配方，而不是只写风格名称。
- **禁用项只禁失败效果**：forbiddenTreatments 写具体的视觉失败（如上面的信号）和许可、事实上不允许的内容；
  不要因为谨慎而一刀切禁止整类媒介，让 worker 只剩几何图标可用。
- **变化密度**：长连续 Scene 的 brief 约每 2–3 秒写出一个可见状态变化，并标出哪些是阅读停留。

## Scene executor：编码前

- **按真实 viewport 设计**：以 `viewportWidth × viewportHeight` 为画布坐标，不在固定正方形 viewBox 中绘制后居中。
  新 full-frame 正文的环境层铺满画面，文字放在 `SceneTextSafeArea` 或等价的冻结矩形中。
- **主体足够大**：关键画面中主体约占画面面积 40–60%，特写可以更大；不把主体关进带边框的卡片。
- **取景要变**：每个 Beat 至少一次取景变化：推近、拉远、平移、换位或主体变形。优先使用已冻结 capability
  （`ProducerShotStage`、`ProducerCamera2D`、`ProducerLayeredStage`、`WhipPan` 等）提供镜头与景深；软件、开发工具与
  开源题材用 `InterfaceWindow`、`TerminalPanel`、`CodePanel`、`RepositoryCard` 呈现真实界面，而不是几个矩形。
- **先看标杆**：新建或大幅重做的 Scene 先读 `remotion-best-practices` 的 exemplar Scenes，借鉴镜头、光影与层级技法；
  内容、构图与时序仍来自当前 brief。
- **变化节奏**：阅读停留之外，约每 1.5–2 秒应有一次可感知变化。阅读停留时文字保持稳定，环境或主体可保留缓慢的
  次级运动（光线、视差、轻微呼吸）；单段完全静止的停留一般不超过约 3 秒，除非 brief 明确要求。
- **代码结构跟上内容**：按物件和镜头拆成子组件，每个组件负责自己的形体、细节与动作。几十秒的多 Beat Scene
  只有几十行代码，几乎必然是幻灯片；任务合同中的最小 Renderer 示例只是 API 骨架，不是规模参考。

### SVG 精作配方

- **分层**：全幅背景板（渐变、光照、环境形体）→ 中景 → 主体 → 前景遮挡 → 稳定文字。
- **体积与光影**：统一光源方向；用 `linearGradient`/`radialGradient` 表达体积，加接触阴影和边缘高光。
- **细节层级**：主体有大形、中形、小细节三级；文档图标、方框、问号和圆点只能作点缀，不能充当主体。
- **线条体系**：全片统一 2–3 种描边粗细与圆角规则。
- **材质**：复用一个共享 pattern 或 `NoiseGrain`，放在主体内部，不逐元素加滤镜，也不盖住阅读文字。

## 音乐与卡点

- **Root**：新片用 studio-v2 引擎，按[原创编曲](score-arrangement.md)让段落跟随叙事：安静的开场、逐步加入脉冲、
  在关键揭示处达到最满的段落、结尾收束。保留辅助脚本给出的 `underSpeechVolume`，让音乐在旁白之间有存在感。
  把 `accentFrames` 写进对应 Scene brief：哪个画面在哪个重音落下。
- **Scene executor**：最大的揭示、切换或镜头到位落在 `musicTiming.accentFrames`/`sectionFrames`，次要动作落在
  `barFrames` 或 `beatFrames`；用 `snapProducerFrameToBeat` 在允许窗口内吸附，预备动作提前开始。语义时序优先：
  吸附不了就保留原帧，不改旁白和字幕。音效对齐同一个落点，不要每个拍点都发声。

## Scene executor：commit 前自审

输出通过 check 后，若绑定提供 `commands.preview` 就运行它；没有 preview 时按源码与时序逐条推演，并把无法观察的项标为
not-assessed。至少查看每个 Beat 的开始后约半秒、动作中段、阅读停留与结束帧，
并在最长停留中取相隔 2 秒的两帧。以下每条都应回答“是”，否则只修改自己的 declared outputs 后重新 check 与 preview：

1. 缩小到手机尺寸，半秒内能认出主体，且主体占画面主要部分。
2. 相邻 Beat 的关键画面构图明显不同，而不是同一布局换文字。
3. 不含字幕时画面上最多一个短标题和一个短标签，且不重复字幕内容。
4. 停留之外，相隔 2 秒的两帧能看出主体或镜头的变化；完全静止的停留不超过约 3 秒。
5. 主体有体积、材质与细节，不是图标、方框、问号或几条线。
6. 环境层铺满画面，没有大块无设计的空底色或居中方框。
7. 有 `musicTiming` 时，Scene 最大的落点位于重音、段落起点或小节线附近（数帧以内），并已记录在 sync-anchors 中。

在最终报告中写明每条结论对应的帧号；预览无法判断的项写 not-assessed。自审结论不是审美批准，
也不替代 Root 对真实成片的审阅。
