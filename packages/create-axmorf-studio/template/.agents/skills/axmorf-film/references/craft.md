# 画面手艺

写剧本前、写代码前、每次审片时读。数值是起点估算，按内容和实测时序调整。

## 先避开最常见的失败：逐页幻灯片

下面这些信号同时出现时，成片读起来像 PPT，而不是影片：

- 每段都是同一堆叠：顶部小标签和大标题、中间带边框的插图卡片、底部说明行、常驻页脚。
- 主体画在固定的正方形里再居中，只占画面四分之一，四周是没有设计的底色。
- 主体由文档图标、方框、圆点、问号和几条线组成，没有体积、光影或细节层级。
- 相隔数秒的帧几乎相同；动作只是在卡片里逐个淡入元素，镜头和主体尺度不变。
- 同一个意思同时写在标题、副标题、标签、说明和字幕里。
- 几十秒、多段落的片只有几十行代码。

最隐蔽的一种是“每段同一版式”：每段都在顶部放小标签和大标题、中间居中一个物体、底部是字幕。物体画得再精致，
观众看到的仍是一页一页翻过去。替代做法：

- 把名称做成场景里的标签（挂在物体上、跟着镜头运动），而不是每段固定在顶部的标题。
- 让多个对象住在同一个空间里，镜头在它们之间移动：例如逐级查询就沿一条路径从一个服务器推到下一个，
  而不是每段把一台机柜摆在正中间。
- 同类对象要在形体、尺度或位置上能区分开，不要每级都用同一个模型换标签。
- 用取景变化（俯视、侧视、特写、全景）区分段落，让相邻两段的构图一眼就不同。

## 构思

- **一句话主张**：观众看完要记住什么。每段旁白都服务这个主张，并让上一段的结果引出下一段。
- **代表画面**：给每段写一句关键画面：取景（特写、全景、俯视、剖面、跟随）、主体位置和大致占比、
  铺满画面的环境、前景遮挡、文字放在哪块安静区。相邻段落的取景要能明显区分。
- **一个连续世界**：同一个空间和主体贯穿多段，用推拉、换位、主体变形完成变化，比每段换一张新卡片更像影片。
  换到另一个空间时用有动机的转场（遮挡、匹配动作、主体放大成为下一场景）。
- **表现手法按主题选**：插画或照片质感用生成图片；精确图解和状态变化用原创 SVG；软件和开发题材用真实界面组件；
  空间结构可用 3D。不要默认用几何图标。

## 设计

- **配色**：定底色、正文、辅助、强调四个角色；强调色只用在关键落点。场景美术可以用题材需要的颜色。
- **主体足够大**：关键画面中主体约占画面面积 40–60%，特写更大；不把主体关进带边框的卡片。
- **按真实画布设计**：以 `useVideoConfig()` 的宽高为坐标，竖屏就为竖屏构图；环境层铺满画面。
- **景深**：后景 → 中景 → 主体 → 前景遮挡 → 稳定文字。用一致的边缘、投影和透明度表达前后关系。
  单屏舞台用 `ProducerShotStage`；要在场景里移动时用 `ProducerWorldCamera`（见“运动与节奏”）。
- **文字预算**：除字幕外，同一时刻最多一个短标题，加上最多 3 个贴在物体上的短标注（名称、数值、单位，如
  “蓝光 450 nm”“氮气 N₂”）。标注挂在它说明的物体旁、随镜头移动，不重复字幕整句。
- **数量要画出来**：旁白里出现数字、倍数、比较或变化趋势时，画成条形、刻度、计数或前后对照，让数值本身可见；
  只把数字写成一行字，静音的观众看不出差别有多大。
- **静音也能看懂**：讲解片的画面要独立讲清机制。关掉声音只看画面，观众应能说出每段发生了什么、为什么。
  来源、日期之类的说明在片尾或发布简介里出现一次。
- **字号**：竖屏 1080 宽时正文标签不小于约 36px，标题 64px 以上；以手机上缩小观看为准。
  字体用 `"Noto Sans SC", "PingFang SC", sans-serif` 一类已安装字体，不依赖合成粗体。

### SVG 精作配方

- **分层**：全幅背景板（渐变、光照、环境形体）→ 中景 → 主体 → 前景遮挡 → 文字。
- **体积与光影**：统一光源方向；用 `linearGradient`/`radialGradient` 表达体积，加接触阴影和边缘高光。
- **细节层级**：主体有大形、中形、小细节三级；图标、方框、问号只做点缀，不充当主体。
- **线条体系**：全片统一 2–3 种描边粗细和圆角规则。
- **材质**：复用一个共享 pattern 或细颗粒，放在主体内部，不逐元素加滤镜，不盖住文字。

## 运动与节奏

- **取景要变**：每段至少一次取景变化：推近、拉远、平移、换位或主体变形。只在原地放大再复位不算：
  每一章至少要有一次真正的平移、跟拍或换位。
- **大场景**：有“过程”的内容（光、信号、物质沿路径变化，因果一环接一环）先把场景搭成比屏幕大的世界
  （例如竖屏三屏宽），各环节在世界里依次排开，用 `ProducerWorldCamera` 让镜头跟着过程走：全景交代 → 沿路径平移
  （`resolveProducerPathPoint` 求路径上的点）→ 推近看机制 → 拉远看结果。远景、主体、前景放在不同 `depth`，
  移动时自然产生视差。画面只有一屏大时，镜头无处可去，只能推拉。
- **变化节奏**：阅读停留之外，约每 1.5–2 秒有一次可感知的变化。停留时文字保持稳定，环境或主体保留缓慢的次级运动
  （光线、视差、轻微呼吸）；完全静止一般不超过约 3 秒。
- **动作分层**：预备 → 变化 → 到达 → 轻微回弹 → 停稳阅读。画面到位的那一帧对齐音乐重音或音效，
  预备动作要提前开始，而不是在落点才入场。
- **画面跟着旁白**：用 `sentence(id).startFrame` 安排对应画面出现，在句子说完前让结果可见；
  不要让画面比旁白早太多揭示答案。
- **代码结构跟上内容**：按物件和镜头拆成子组件，每个组件负责自己的形体、细节和动作。

## 讲述段与节拍段

同一部片按时间段切换两套做法，不按片子类型二选一：

| 时间段                                               | 做法                                                                                                                                                                                        |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 讲述段：有旁白在说                                   | 画面跟着旁白语义走；一个主镜头至少撑完半句；字幕区干净，不叠撕裂、错位和闪白；镜头稳定，只保留缓慢的次级运动                                                                                |
| 节拍段：开场钩子、段落转场、句间停顿、高潮揭示、结尾 | 跟着音乐剪：切点取自 `barFrames`/`beatFrames`，最大的落点对齐 `accentFrames`；可以用 `ProducerBeatCamera` 跟鼓推镜、`ProducerSpriteSheet` 播放动作表、`ProducerWhipIn` 甩镜入场、闪白和撕裂 |

讲解片可以在开场和章节转场放几秒节拍段，让片子有呼吸；MV 和 OP 几乎整片都是节拍段。需要更长的节拍段时，
给对应句子加 `pauseAfterMs`。节拍段的画面照样要有内容：它最容易暴露素材不够，`film:review` 的
`repetitionWarnings` 专门检查这些时段。

## 审片

运行 `film:review` 后打开联系表和单帧。每轮都逐条回答，并写出支撑结论的帧号（例如“2：f402 俯视芯片、
f474 侧视机柜，构图不同”）；答不出帧号就当作“否”。“否”的项改完再审：

1. 缩小到手机尺寸，半秒内能认出主体，且主体占画面主要部分。
2. 相邻段落的关键画面构图明显不同，而不是同一布局换文字；没有出现“每段顶部标题 + 居中物体 + 底部字幕”的固定版式。
3. 不算字幕时画面上最多一个短标题和 3 个贴在物体上的短标注，且不重复字幕；`readabilityWarnings` 中字号过小、文字越界的提示
   为空，或每条都有明确理由。
4. 停留之外，相隔 2 秒的两帧能看出主体或镜头的变化；`stillWarnings` 为空，或每条都有明确理由。
   结尾也算：最后一句说完后的画面同样需要缓慢的次级运动，不要整段定格。
5. 主体有体积、材质和细节，不是图标、方框、问号或几条线。
6. 环境铺满画面，没有大块没设计的底色或居中方框。
7. 字幕不遮挡关键内容，`readabilityWarnings` 中被字幕遮挡的提示为空，或每条都有明确理由；画面文字与背景对比清楚
   （对比度仍需看图判断）。
8. 有配乐时，最大的揭示或切换落在重音、段落起点或小节线附近（数帧以内）。
9. 封面两种尺寸都有清楚的主体和大标题，不是正片某帧的简单缩放。
10. 节拍段（没有旁白的时段）没有反复回到同一个画面；`repetitionWarnings` 为空，或每条都有明确理由。
11. 静音测试：关掉声音只看联系表和单帧，每段的机制都能看懂；旁白里的数字都以可见的数量出现（写出帧号）。
12. 镜头不只有推拉：每章至少一次平移、跟拍或换位，写出起止帧和移动方向。
13. 字幕在手机上清楚：没有为排成一行缩小字号；`readabilityWarnings` 里没有 `small-caption`。

联系表只能看构图和状态，看不出运动是否流畅；需要时让用户在 `npm run dev` 里播放确认，并在报告中说明哪些项没有实际看过。
