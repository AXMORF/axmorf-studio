# v0.1.6 Workspace reliability follow-up

## Incident and source changes

The published v0.1.5 Workspace completed a real Hermes video but failed the next Codex doctor before production.
Fixed Node.js 22.22.3 reproduced `SIGKILL` of an exiting browser process group returning `EPERM`, then an empty process
group listing and `ESRCH`. The shared bounded-process close callback threw outside its controlling Promise, so the caller
lost the child status/output and doctor crashed. Node.js 26.4.0 also reproduced the original error outside Codex.

[Apple XNU killpg1](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/kern_sig.c) filters zombie group members
and can return EPERM when no signalable members remain. This supports the observed exit-race explanation; EPERM alone
must never be treated as successful cleanup. A read-only liveness observation must prove the owned group has disappeared or, after child close, contains no live member,
while real or unknown permission failures remain failures. No browser sandbox is weakened and no provider/production retry
is introduced.

The public final-check route also still used old narrative-baseline media receipts that current production does not emit.
Current Delivery inspection verified the Hermes bytes. The public route now validates current Revision, artifacts and
four-file Delivery; the explicit development proof workflow keeps its separate baseline contract.

## Verification and release

- The original cleanup-error regression failed before the fix; genuine permission denial, output retention, ownership
  registration and deadline cases are covered without weakening failures.
- A signal-zero-only check still reproduced the real browser exit race. The strict Darwin close-time process snapshot
  implementation then passed ten consecutive real 16×16 PNG renders on fixed Node.js 22.22.3 against the existing Workspace.
- Sixteen public final-check regressions passed, including missing legacy proof files, zero-write verification, checksum drift,
  stale Revision/artifact set, dirty artifacts, input changes during inspection, and six self-consistent but incorrect media specifications.
- The new public adapter also verified the actual v0.1.5 Hermes Delivery using its installed runtime manifest: artifacts,
  media, Revision, artifact set, expected DeliveryBuildId, audio channels and snapshot all passed, with no writes.

Complete repository checks passed with 776 tests and no failures or skips. Package build/typechecks, lint, documentation links,
resource/registry checks, compositions and host checks passed. Three additional doctor runs using the built CLI also passed.
Publication and fresh two-Agent acceptance are pending.
