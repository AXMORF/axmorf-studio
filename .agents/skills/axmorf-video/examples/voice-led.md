# 有口播：语义主导的连续场景 brief

方法与 [音乐主导示例](music-led.md)相同，但先生成并封存旁白，再依据真实时段做动作。以下话语仅用于解释设计，不是已生成的配音或逐词时间戳。

**示例口播**：“一个想法，先把它做出来，再让别人看见。”

主体是一张纸：先出现草图，再在同一空间组装成一个可辨认的物体，最后展开为可查看的成果。标题不复述整段字幕，而概括当前结果。Composition 已拥有字幕，Scene 不重画。

| 测得的语义范围 | 主体变化 | 拍点选择 | 混音 |
| --- | --- | --- | --- |
| 解释“想法” | 草图出现，保留初态 | 开始可以离拍；让内容先被理解 | 少量拨弦、低密度 |
| 解释“做出来” | 草图变成物体，完成组装 | 从 prepared `scene.musicTiming` 中选处于本段动作窗口内的落点 | 接触音简短，不遮住关键音节 |
| 解释“让别人看见” | 同一物体展开、露出结果 | 若附近无适合拍点，按语义展开，音效跟动作 | 伴奏留空间，结果保持 |

具体 frame 范围来自 sealed PCM 与 SemanticTiming，不能拿这个表中的顺序当作已经测得的时间。chunk 范围也不能用来断言某个字的起始帧。需要精确逐词对应时，应使用当前真正提供的时间信息，缺失就保持合理的语义窗口而不伪造。

## 实现时的顺序

1. Root 按当前 create context 写完整旁白与 filmPlan，冻结代码合成的配乐循环。配乐长度不反向规定配音时长。
2. prepare 得到封存旁白、真实边界和 Scene-local musicTiming。worker 绑定后读取本次输入。
3. 在允许语义窗口内决定动作接触帧；提前入场、接触后余振，再保持可读结果。不能叠加全局偏移两次。
4. 为重要动作填写当前支持的 sync anchor 与 SoundContributions；音源已批准，冲击对起音、swell 对描述的中心。
5. 保留固定旁白、字幕和边界；音乐减密度或减音量，让口播清楚。不要为了音乐改 TTS、插入停顿或重封 PCM。
6. 看真实画面、听最终混音；如需改正文设计，按正式 revision 进行。缺少试听能力时只报告实测音频数据与未试听。

口播并不要求静态卡片。它限制的是语义时间与混音空间，构图、物体动作、材质、连续镜头和安静转场仍可充分设计。
