# 视频创作手册

适用：Root 规划新片、重做正文、审阅真实媒体。技术生产仍按 [film direction](film-direction.md) 与当前 Skill；本文不增加输入字段、文件权限、审美验收器或发布权限。

来源是用户提供的 Claude Opus 5.5《PLAYBOOK.md》和 `video-playbook.zip`。保留其具体设计方法，修正与当前项目的衔接；[原文与来源说明](../examples/opus-playbook/README.md)可追溯。横屏、无口播、100 BPM、剪纸和原案例的段落数都不是通用要求。

## 先做设计，再开始动

制作前先回答“观众看到了什么变化”，再回答“用了什么动画”。网站介绍不必依次播放栏目卡片：可以让零散想法汇成作品、让一个对象展示不同能力、让网页里的关系成为空间里的关系。具体事实先核对真实来源；不要编造用户数、排名、界面和项目能力。无数据的图形应明确是示意。

在 `story.filmPlan`、现有 artDirection 和 Scene brief 中写明：

| 决策 | 要写清的内容 |
| --- | --- |
| 中心意思 | 观众最后记住什么；哪个可观察变化证明它 |
| 主体与空间 | 哪个物体承担叙事；初态、动作、结果；为何要切换空间 |
| 完整画面 | 主体的位置和尺度，标题与注释层级，留白、重叠、前后关系 |
| 色彩与材质 | 已冻结 theme 的角色分工与面积关系；字体实际可用；纹理、边缘、投影的配方 |
| 节奏与镜头 | 哪些动作聚集、哪里安静；相机为什么移动、在哪里稳定 |
| 声音 | 乐器与编曲能量如何变化；重要事件用什么音效；哪些事件保持安静 |

“高级、活泼、有设计感”不能代替这些决定。先画或实现一张主要元素都到位的完整画面，检查它是否值得观看，再为它设计入场。不要从一个默认标题加卡片布局开始，以为把元素依次弹出就完成了设计。

自主构思时可以先列两三个不同的视觉隐喻，由创作者按内容选一个，不必把例行选择交回用户。不同章节用不同物体动作表达差异；同一物体可以连续变形或转移焦点。卡片和列表在需要比较、排序时有用，不能自动成为所有内容的共同构图。

## 完整画面如何成立

1. **主角清楚**：先调主体尺度、位置、留白和对比，让视线有落点。空白不等于缺少装饰；不要用小图标填满每个空位。
2. **层级清楚**：标题、物件、说明、注释承担不同任务。大面积色块决定第一眼，点缀色只强调关键变化；不能只修改几条边框就宣称全片配色丰富。
3. **关系清楚**：遮挡、接触阴影和方向让物体有前后。用实体的组装、折叠、连接、展开解释内容，装饰图形不能冒充因果。
4. **文字能读**：按实际 viewport、minFontSizePx、真实字体和最终缩小画面判断；长句自然断行，短标签可以不换行。网址、点号、CJK 字形和真实字重都要看实际像素。
5. **材质一致**：先保留颜色，再叠轻颗粒、边缘和阴影。纹理不能把整个画面染灰；每个小元素都加噪声滤镜既昂贵又容易脏。

theme 四角色保护兜底背景、文字与品牌。新 full-frame 正文可独立设计图片、材质、场景光色与遮挡；文字遵守局部对比和独立安全区，不能照搬参考片文字到复杂背景。旧片保留冻结边界。

剪纸的具体工艺见 [纸拼贴案例](paper-collage.md)。其他风格也要给出可执行配方，如实物摄影的裁切与光线、技术画面的空间关系与光效；不要让“学习案例”变成固定纸张滤镜。

## 叙事与阅读决定密度

原文的“钩子—身份—理念—作品—链接—收束”是该网站案例的结构。下一部片先按内容组织，允许一个连续长 Scene 承担多个语义 Beat，也允许安静切镜或淡出。Scene 边界由主体、空间和动作连续性决定，不按句号、工作分配或六七段配额决定。

起承转合要在动作里发生：看到初态，理解变化，再看到结果。钩子放在继承的片头允许的位置；固定片头片尾的时间先扣除，不擅自关闭或缩短用户设计的边界。

每个文字的阅读预算从“完整可读”算到“被遮住、移走或缩小到不可读”。入场与回弹不能全部算作稳定阅读时间。新中文约每秒 4–6 字、短标签约 0.8–1 秒可作估算，最终按理解难度、实测配音和真实画面调整。原案例的快速小标签不是可读性的合格证明。

安排一段密集动作后留出稳定结果；关键结论需要更长停留。不要为了满拍把所有层持续晃动，也不要给每次变化都加相机冲击或音效。

## 一张事件表，连接画面和声音

先定义事件的含义，再安排视觉与音效。制作阶段让可见动作、sync anchor 和 sound contribution 引用同一个事件。

| 事件部分 | 例子：纸片盖章 |
| --- | --- |
| 预备 | 落点前 12 帧开始下降，观众预知动作 |
| 接触落点 F | 纸片触地、印章接触；冲击音的起音对齐 F |
| 余振与稳定 | 接触后有轻微回弹；稳定后才开始主要阅读预算 |
| 结果 | 印章含义清楚并保持；下一动作由结果引出 |

“落点”不是动画起点，也不必等于完全静止。短 whoosh 对齐的是设计的膨胀中心；冲击、盖章常对齐起音。音源的最大单个采样不一定是感知落点，不能把全部音效都机械地按峰值对齐。

若事件目标帧为 F，音源中选定对齐点的偏移为 O 个采样：

```text
目标采样 = round(F / fps × sampleRate)
播放起点 = 目标采样 - O
```

小于零时重新设计事件或裁切并复核，不偷偷改变故事起点。不同时间轴要显式换算：当前 `scene.musicTiming` 已是 Scene-local，不能再叠加全局 Scene 偏移。帧、秒和采样不是同一单位。

独立音乐节拍计算应按绝对位置取整：

```text
beatFrame(k) = round(k × 60 × fps / BPM)
```

每拍不需要整数帧。不要先四舍五入一拍长度再累计，否则长视频会漂移。小样采用 97 BPM，专门展示这种非整数情况。

## 口播与音乐可以结合

有口播时先生成并封存配音，PCM 采样决定语义时段、字幕和边界。拿到准备阶段的 `scene.musicTiming` 后，在允许的动作窗口里选择邻近音乐落点。重要语义也可以离拍；不能改配音速度、插入沉默、移动字幕或重新生成 TTS 来迁就节拍。chunk 范围不是逐词时间戳。

例如口播开始解释“连接”，连接线可提前铺开，在该语义范围内的某个重拍完成接触，再让结果保持到下一意思。没有合适重拍时，动作按语义落下，音效跟动作；音乐让位。

无口播时可以按音乐乐句安排动作与段落，仍需为文字理解留时间。可用 visual-first 或显式 authored-frames，但不要先做口播再删除音轨冒充无口播流程。

分别看 [音乐主导 brief](../examples/music-led.md) 与 [口播主导 brief](../examples/voice-led.md)。两者采用同一套构图、事件和阅读方法，只是时间权威不同。

## 代码配乐与混音

新片按 [现有代码合成入口](film-direction.md#code-synthesized-music-and-shared-timing)冻结配乐 WAV/timeline 后创建 Project。不要换成原作者的命令链或强行升级 Remotion。原文的 C 大调、I–V–vi–IV、拨弦乐器和音量值是一个音色方案，可以更换。

配乐设计需要同时考虑音色和编曲：开头稀疏，动作聚集时加入节奏与低音，中段加入对位或音色变化，阅读时减少密度，结尾收束。一直循环同样四小节再整体调大，不能自动带来节奏感。

音效承担具体动作：纸片接触用 slap，重要盖章用 stamp，滑动用 swell，小注释用 pencil，小确认用 ding。没有必要每张标签都 pop、每次切镜都 riser。音效和音乐分轨处理，既能让重要接触突出，也能在安静段留白。

有口播时保留人声的频段和时间空间，必要时降低伴奏、减少乐器或做局部 ducking；具体 gain 不证明最终响度。无口播时音乐可更有存在感，仍要避免重要音效被掩蔽和 AAC 编码后过峰。

正式 Composition 拥有兜底背景、音乐、旁白、字幕，SoundDesignTrack 播放音效；Scene root 透明，子层可铺满场景美术，文字留在独立安全区，不挂 Audio 或生成配乐。全片音乐不中途因 Scene 或语义 Beat 重启。教程 `lesson.wav` 是独立小样的混合轨，**不得作为正式 BGM 导入后再重复播放相同音效**。

## 验证构图、动作与混音

在生产允许的预览阶段检查真实媒体；已提交的 artifact 不覆盖，正式改动走 revision。预览结果和技术 receipt 不能替代设计判断。

| 观察范围 | 具体判断与修复 |
| --- | --- |
| 完整构图、缩小观看 | 主角不突出就改尺度、位置或背景对比；不要只再加装饰 |
| 动作中段 | 检查穿插、过大回弹、文本随相机缩小；修改动作和层级 |
| 接触前后 F−1/F/F+1 | 确认真实接触帧；核对音源对齐点与采样起点 |
| 稳定阅读与相机极值 | 检查字体、断行、遮挡、边界；需要就延长可读停留或减字 |
| 整段变化与接缝 | 检查物体位置、方向、速度、身份是否延续；静帧不能证明运动连续 |
| 解码后的成片音频 | 听重要事件是否可辨、口播是否被遮蔽；量最终 AAC 的响度和 true peak |

记录“看到了哪个问题、如何修、复查哪段”，而不是只写好看或技术通过。先修影响叙事与可读性的缺陷，再调细节。

证据绑定实际媒体哈希与 preview/Delivery ID，区分抽帧、连续观看、测量和试听。没有音频播放能力就明确未试听；低频 RMS、相关系数或音量检测不能证明整片卡点和音乐感染力。原作者的验收陈述是来源材料，不自动成为本项目的验证事实。
